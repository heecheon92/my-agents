## 운영자 가입 알림

`MY_AGENTS_REGISTRATION_NOTIFICATION_EMAIL`에 운영자 수신 주소를 설정합니다. 미설정 또는 빈 값이면
이벤트를 큐에 넣지 않고 전송 worker도 시작하지 않습니다. 기존 대기 작업은 보존되며 다시 설정하면 재개합니다.
설정 전의 계정은 소급 알리지 않습니다. 개인 수신 주소를 저장소에 넣지 마세요. SMTP/Resend는 기존 auth-email
설정을 재사용하며, local 모드는 `/auth/dev/outbox`와 분리된 메모리에 운영자 알림을 기록할 뿐 전송하지 않습니다.

일반 가입(승인 대기 포함), 그룹 초대를 통한 새 계정 생성, 게스트 코드 사용으로 계정이 생성될 때만 알립니다.
코드 요청·재전송, 가입 실패, 일반 로그인, 이메일 인증, 기존 회원의 초대 수락에는 알리지 않습니다.
게스트는 요청 기록의 실제 이메일을 사용하며, 이메일 없이 발급한 운영자 코드이면 미제공으로 표시합니다.
본문에는 이벤트 종류, 사용자 ID, 이메일, UTC 생성 시각, 생성 시 승인 상태, 게스트 만료 시각만 넣습니다.
비밀번호나 코드를 포함하지 않습니다.

배포 전 `uv run alembic upgrade head`로 `20261003_0037` migration의 `registration_notifications`
테이블을 생성합니다. 계정과 알림 이벤트는 같은 transaction에서 저장합니다. 백그라운드 전송은 파일 기반 SQLite 또는 PostgreSQL이 필요합니다. 메모리 SQLite에서는 요청 연결과의
충돌을 막기 위해 worker가 경고를 남기고 종료합니다. 격리된 테스트에서만 동기적으로 큐를 처리할 수 있습니다.
종료 시 현재 전송만 마칠 때까지 기다리고 다음 작업은 가져오지 않습니다. 활성화된 FastAPI lifespan worker가
시작 시점과 각 batch 처리 후 30초마다 최대 25건을 처리하며, 제공자 호출은 event loop 밖에서 수행합니다.
원자적인 lease로 일반적인 worker 간 중복 처리를 막습니다. 전송 실패는 최대 1시간 간격의 지수 backoff로
재시도하고 만료된 lease는 복구합니다. 알림 전송 실패가 가입 요청을 실패시키지는 않습니다.

수신 주소는 이벤트 생성 시 고정합니다. 설정 변경은 새 이벤트에만 적용하며 대기 이벤트는 원래 주소를 유지합니다.
설정 변경 후 앱을 재시작하세요. 비활성화 후 재시작하면 대기 이벤트도 전송하지 않습니다. 이미 진행 중인 전송은
취소를 보장할 수 없습니다. 제공자 수락 직후 성공 저장 전에 프로세스가 종료되면 중복 알림이 생길 수 있는
**at least once** 전송입니다. 제공자의 수락이 실제 받은편지함 도착을 뜻하지는 않습니다.

성공한 큐 항목은 두 이메일 주소를 지우고 이벤트·사용자 ID, 종류, 시각, 승인·만료 상태, 시도 횟수만 남깁니다.
사용자 FK가 없으므로 향후 게스트 삭제 후에도 최소 전송 기록을 유지할 수 있습니다. 실패 항목은 재시도를 위해
주소를 보존하며, 기록 자동 만료 정책은 아직 없습니다. 이 큐는 이메일별 남용 방지 기록이 아니며 게스트 재가입 제한이나
만료 계정 정리를 구현하지 않습니다.

오프라인 검증은 세 가지 계정 생성 경로, 비활성화, 중복 가입·코드 재사용, rollback, local outbox 격리,
재시도, lease 복구, migration/schema 일치를 확인합니다. 실제 SMTP/Resend 전달, 받은편지함 도착,
PostgreSQL 동시성은 별도 배포 검증 대상입니다.
